# GitHub 飙升雷达 · 系统设计手册

> **单文件手册**:整合系统总览、数据库表结构、后端接口与服务层逻辑、采集与多线程、
> AI 概要提取机制、前端页面细节与样式规范、部署运行。配合同目录 `sql/` 脚本,
> 可完整理解本项目的实现方式。

## 项目是什么

一个面向 GitHub 开源项目的**数据大屏 + 榜单 + AI 概要**系统:

- 按「star ≥ 50 且 3 年内有更新」的默认口径,从 GitHub 全量收口项目入库;
- 采集 star 每日/每周历史,落事实表,算出日榜/周榜/月榜、总榜/飙升榜;
- 调用大模型阅读 README,为项目生成**中文概要**(强制中文、一次性生成不重复);
- 提供大屏看板、多维筛选榜单、项目详情、关注提醒、采集调度、模型任务管理共 6 个页面。

## 5. 端到端数据流

1. **收口**:`search_harvester` 按 star 区间递归分页从 GitHub Search 拉项目 → `repo_service.upsert_repos` 写入 `gh_repo`。
2. **补全**:`repo_collector` 拉详情(协议/语言/参与者/最新版本)→ 更新 `gh_repo`;`readme_collector` 写 `readme_en_url/readme_ch_url`。
3. **历史**:`history_collector` 拉官方周聚合 → `facts_service.save_history` 同时写 `gh_repo_star_weekly`(周)与 `gh_repo_star_daily`(每日)。
4. **事实回填**:`facts_service.rollup_gains` 回填 `star_gain_1d/7d/30d/60d` 与 `daily_velocity`。
5. **快照/榜单**:每日 23:50 快照;周榜计算写 `gh_rank_snapshot`(完整周期冻结 `is_final=TRUE`)。
6. **AI 概要**:`llm_service` 按「任务 → 模型」批量并发调用,结果写 `gh_repo.ai_summary`,记录 `gh_llm_run`。
7. **展示**:前端 `Radar.api` 调 `/api/...` 拿 `{code:0,data}`,Vue 渲染 + ECharts 绘图;悬浮看概要、点击进详情。

# 04 · 后端服务层逻辑

> 服务层位于 `app/services/`,承载全部业务规则:排序、过滤、UPSERT 合并策略、榜单口径、
> 快照冻结、事实回填、调度、补缺。API 层只做参数装配与调用。

---

## 1. `repo_service.py`(约 502 行)—— 仓库读写核心

### 1.1 排序白名单 `SORT_MAP`
前端传入的 `sort` 经白名单映射到 SQL 列,防注入:`stars/forks/gain_1d/gain_7d/gain_30d/gain_60d/`
`velocity/updated/pushed/release/seen/name`。`list_repos` 固定追加 `stars DESC, full_name ASC` 作为稳定次序。

### 1.2 UPSERT 合并策略(全项目最关键逻辑之一)
以 `full_name` 为唯一键,`ON CONFLICT(full_name) DO UPDATE`,`UPSERT_COLS` 约 41 列。不同列采用不同合并规则:

| 分组 | 列 | 规则 |
|------|----|------|
| `_ALWAYS` | sources、seed_metrics、is_major、stars、forks、watchers | sources/seed_metrics **合并去重**;is_major 取「或」;stars/forks/watchers 用**非 0 覆盖** |
| `_KEEP_TEXT` | summary、description、lang、license、homepage、readme_*、latest_version、version_note | **只填空**(已有非空值不覆盖) |
| `_KEEP_TS` | 各类 synced_at 时间 | 只填空/按需更新 |
| `_KEEP_CONTRIB` | contributors_count | 已有正数则保留 |
| 其余 | — | `COALESCE(EXCLUDED.x, 现有)` 保留非空 |

- `_defaults` 补全缺失列:对 `topics/sources/seed_metrics` 用 `Json()` 包装,数值转 int,并校验 `full_name` 含 `/`。
- `upsert_repos_report(rows)`:入库同时判断哪些是**新项目**,返回 `{upserted, new, new_names}`。
- `upsert_repos(rows)`:批量 upsert,返回条数。
- `refresh_major_flags()`:按 `gh_rank_whitelist` 中 `list_type='major' AND enabled` 同步 `gh_repo.is_major`。
- `save_contributors(repo_id, list)` / `save_releases(repo_id, list)`:参与者与版本明细落表。

### 1.3 过滤条件 `_filter_clauses`
**默认口径**:`stars >= min_stars(默认50)` **且** `COALESCE(repo_pushed_at, repo_updated_at, repo_created_at, first_seen_at) >= now() - max_age_days(默认1095)`。
`min_gain` 取 `GREATEST(star_gain_1d, star_gain_7d, star_gain_30d, star_gain_60d)`。多条件以 AND 组合。

### 1.4 查询与候选
- `list_repos(...)`:主查询,支持关键词/多语言/协议/topic/source/major/archived/has_summary;`top_n` 时忽略分页。
- `get_repo(full_name)`:单仓详情聚合。
- `list_langs(min_stars, limit)` / `list_licenses(min_stars, limit)`:筛选项选项池。
- `candidates_for_detail(limit, ids, only_missing)` / `candidates_for_history(...)` / `candidates_for_readme(limit, ids, refresh_after_days=30)`:按断点续采规则挑待采仓库。
- **历史采集选仓两档阈值**:`_HISTORY_TIER_HIGH=20`、`_LOW=5`、`_CUTOFF=1000`,`history_gain_threshold()` 依据仓库热度决定优先度(高热度先采)。

## 2. `rank_service.py`(约 319 行)—— 榜单口径

- `BASE_FILTER`:star 下限 + 3 年内更新的基础过滤。
- **`live_rank(period_type, metric, ...)`**:实时榜单,三种口径:
  - `total`:按 `gh_repo.stars` 排序(总榜);
  - `gain`:**事实口径**,`JOIN gh_repo_star_daily`,对区间 `SUM(delta_stars) HAVING > 0`;
  - `gain_index`:**滚动口径**,按 `star_gain_1d/7d/30d`(日/周/月分别对应)。
  - 返回含 `coverage`(各可选列的数据覆盖度),前端据此**智能隐藏空列**。
  - 排序走 `_SORT_COLS` 白名单,全库排序。
- `period_overview(...)`:周期概览,**优先读快照**,无快照回退实时。
- `top_movers(...)`:近 N 天飙升(大屏右列用)。
- 白名单 CRUD:`whitelist_list / whitelist_add / whitelist_remove / whitelist_toggle`,变更后调用 `refresh_major_flags`。

---

## 3. `snapshot_service.py`(约 344 行)—— 快照计算与冻结

- `daily_snapshot(...)`:每日快照(内部走 facts_service)。
- **`compute_rank(period_type, period_key, metric, force)`**:
  - metric ∈ `total/gain/gain_index`;
  - **完整周期首次计算即冻结**:写入 `gh_rank_snapshot`,`is_final=TRUE`;
  - 已冻结 + 周期完整 + 非 force → 返回 `skipped`;
  - 未走完的当前周期可反复更新(不冻结);
  - 同时写 `gh_stat_period` 元信息。
- **`ensure_period(...)`**(榜单页「立即补齐该周期数据」):
  - 以 `_ENSURE_LOCK` + `_ENSURE_INFLIGHT` 防重入;
  - 若 `metric=gain` 且区间无每日事实 → 调 `history_collector` 补采(`HISTORY_LOOKBACK_DAYS=210`,预留额度 `reserve=50`);
  - 再按同一时间区间规则计算并入库。
- `compute_all_ranks(...)`:自 2025-01-01 批量计算,返回 computed / skipped 计数。
- `list_periods` / `get_snapshot` / `stat_periods`:快照查询。

## 2. `github_client.py` —— GitHub 客户端与全局限速(约 334 行)

## 4. 批量提取机制 `_run_ai_summary`(重点)

针对 `repo_ai_summary`,把仓库**分组**,一组一次 LLM 调用,输出用 `### <full_name>` 分块:

1. **只补空过滤**:`allow_overwrite=False`(默认)时,先剔除已有 `ai_summary` 的项目 —— **已有概要不重生成、不覆盖**(只新增不减少),即使显式指定 id 也跳过。若全被剔除则直接返回提示。
2. **分组**:`groups = [repos[i:i+group_size] for ...]`,`group_size` 默认 10(UI/调度可传 15~25)。
3. **README 中转**:每组先把组内 README **并行下载**(`ThreadPoolExecutor(max_workers=min(10, len(group)))`,IO 密集)到 `server/readme/<owner__repo>.md`(走 raw CDN,不计 API 额度),拼成材料:
   ```
   【{full_name}】
   语言:{lang} 协议:{license_spdx}
   官方简介:{description}
   README:
   {readme[:max_readme_len]}
   ```
4. **批量提示词**:
   - `_SUMMARY_SYS_BATCH`:`你是开源项目分析助手。阅读给定项目材料后,用流畅、简洁、有逻辑的中文写成一段或几段项目介绍,自然讲清楚:它是什么、有什么用、主要功能,像一段得体的小简介。禁止分点罗列、禁止小标题、禁止复述指令、禁止输出思考过程或与本项目无关的内容。`
   - `_SUMMARY_TPL_BATCH`(含 `{n}` 与 `{materials}`):
     ```
     共 {n} 个项目。请为每个项目用流畅的中文写 1~3 段话做介绍,自然涵盖:它是什么、解决什么问题、主要能力;语言要通顺连贯、有逻辑,不要分点、不要"做什么:"这类小标题、不要任何额外说明。每个项目以一行 "### <full_name>" 开头,随后紧跟正文(总字数约 120~250 字):
     ### <full_name>
     <1~3 段中文介绍>

     项目材料:
     {materials}
     ```
5. **解析返回**:
   - `_split_blocks(text, names)`:优先按 `### <full_name>` 标题行定位切块,**避免前言/思考中出现的名称造成错位**;无标题行再回退「任意包含该名称的行」。
   - `_strip_summary_body(block)`:去掉块首标题行(以 `###` / `【` / `项目:` 开头的行)。
6. **落库与校验**:每个项目 `body` 通过 `is_valid_summary` 才写入(带 `AND COALESCE(ai_summary,'')=''` 防并发覆盖);不合格则 `_bump_summary_tries` +1。
7. **整组失败降级**:调用失败(风控/超长)时,若组>1 → **拆成单项逐个重试**,隔离问题项,避免一颗雷拖垮整组。
8. **清理**:`finally` 里删除本组 README 中转文件(不长期留存)。
9. **并发**:`run_threaded(groups, one_group, concurrency=workers)` 多线程执行各组。


- `is_chinese_summary(t)`:CJK 字符数 ≥ 20。
- `is_valid_summary(t)`:通过中文校验 **且** 不以 `#` 开头(无 Markdown 小标题)**且** 长度 ≤ 900 **且** 不含任一禁词(防指令复述/前言)。
- 不合格:**一律丢弃、不落库**,只对仓库累加 `ai_summary_tries`;达 3 次后 `_pick_repos` 不再自动选中(避免「一个项目被无数次重试」)。

---

## 6. 选仓策略

- `_pick_repos(task, limit, ids)`:
  - 指定 `ids` 时按 id 取;
  - `repo_ai_summary`:`stars>=50 AND ai_summary='' AND ai_summary_tries<3 ORDER BY star_gain_7d DESC NULLS LAST, stars DESC LIMIT n`;
  - `repo_summary`:`summary='' AND stars>=50` 按 7 天增量排序;
  - `version_note`:`version_note='' AND latest_version IS NOT NULL` 按发布时间排序。
- `pick_month_top(limit=2000, since_days=30)`:取最新**月榜 gain** 前 N,其中「从未提取且未超次数」或「已提取但距上次 >30 天」。
- `run_month_top(...)`:月度刷新,**绝不遍历全库**,入口仅来自调度 `ai_month_top`;`allow_overwrite=True` 允许覆盖(仍受选仓控制)。

---

## 7. 执行与可观测

- 每次调用都先插入 `gh_llm_run(status='running', prompt=...)`,结束后更新
  `status ∈ {success, partial, failed}`、`output`、token 统计、`latency_ms`、`error`、`finished_at`。
- `run_task(task_key, model_id, limit, ids, concurrency, group_size, allow_overwrite)`:
  解析模型(显式 → 任务绑定 → 默认),`_pick_repos`,按 task_key 分流到 `_run_ai_summary` 或通用逐仓模板渲染。
- 通用任务写回:`repo_summary→summary`、`version_note→version_note`、`repo_ai_summary→ai_summary`,其它 task 写 `gh_watch_event`。
- `list_runs`(limit/task_key/status)、`run_stats`(runs/success/failed/tokens/avg_latency_ms)。

---

## 8. 要点清单

1. **概要必须中文 + 模板合规**,不合格丢弃;这是硬需求。
2. **批量 + 分块**:一组一次调用,`### full_name` 分块解析。
3. **多线程双层**:组间 `run_threaded`,组内 README 下载再 `ThreadPoolExecutor`。
4. **一次性生成**:只补空,月榜前 N 才允许覆盖刷新。
5. **失败上限**:`ai_summary_tries` 上限 3。
6. **配置外置**:供应商/模型放 `data/llm_config.json`(DB 只读表),密钥脱敏返回。

## 9. 常见问题

| 现象 | 处理 |
|------|------|
| 本机 curl 502/超时 | 加 `--noproxy '*'` |
| 采集全部失败 | 检查 `GH_PROXY` / `GH_GITHUB_TOKEN`;额度可在 `/system.html` 头部或 `/api/system/rate-limit` 查看 |
| 概要生成后为空 | 模型返回不合格(非中文/格式不符)被硬校验丢弃,查 `gh_llm_run.error` |
| 页面样式不更新 | 静态资源已 `no-store`,正常强刷即可 |
| 端口占用 | 改 `GH_PORT` 或查占用进程 |
